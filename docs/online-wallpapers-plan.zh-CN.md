# 在线壁纸方案草案

在线图库目前仍为方案，尚未接入外部素材、创建在线仓库或启用图库后台联网。v0.8.0 已实现的本地壁纸右键删除与这份方案独立。

## 推荐的交互

壁纸页增加「本地壁纸 / 在线壁纸」入口，在线页提供「全部 / 静态 / GIF / 视频」筛选、名称搜索和刷新。

进入在线页才请求目录与当前可见卡片的缩略图。每张卡片展示封面、名称、分辨率、文件大小和下载状态，详情展示作者、来源页和许可链接。默认只加载静态封面，GIF、视频在用户选中预览时最多播放一个，离开页面即停止，避免同时运行大量解码器。

下载按钮依次显示「下载原文件 → 下载中（可取消）→ 已下载 / 应用」。成功后加入本地壁纸库，断网也能应用。原文件不重编码、不降低分辨率；缩略图可以单独缩小以节省浏览流量。

「已下载」应由素材 ID、版本、已有的本地条目和文件是否存在共同判断，不能只存一个布尔值。删除本地壁纸后恢复可下载状态；用户手动删掉文件时也不能继续显示已下载。相同 ID 的原文件更新后，显示可更新状态。

首次断网显示明确的重试入口。已有目录缓存时仍可浏览缓存的封面和已下载素材，不因断网清空内容。软件启动时不预下载整个图库。

## GitHub 保存索引，原文件单独分发

建议后续建立独立的 `light-block-wallpapers` 仓库，维护经过审核的 `catalog.json`、小封面和逐项许可记录。目录更新不需要重新发布桌面软件，用户刷新在线页即可读取新版目录。这个仓库当前尚未创建。

小型目录和封面可放在 Git；大图、GIF 和视频按许可放在独立资源 Release 或允许再分发的素材存储中，目录保存原文件 URL。GitHub 对普通 Git 文件有大小限制，不适合把视频不断提交到软件源码仓库。[GitHub 大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)

JSON 使用一个明确的 `schema_version`，目录项至少包含以下字段。

| 字段 | 用途 |
| --- | --- |
| `id`、`revision` | 稳定素材标识和内容版本 |
| `title.zh`、`title.en`、`kind`、`tags` | 中英名称，`image / gif / video` 分类和搜索 |
| `thumbnail_url`、`download_url` | 独立封面与原文件 HTTPS 地址 |
| `filename`、`bytes`、`sha256` | 确认文件名、预估下载量及原文件完整性 |
| `width`、`height`、`duration_seconds` | 分辨率，动态素材的时长 |
| `author`、`author_url`、`source_url` | 原作者及作品来源页，作者不能只写上传者 |
| `license`、`license_url`、`attribution` | 每个素材实际适用的许可和署名文字 |
| `changes`、`reviewed_at` | 是否裁剪、转码等修改，以及授权核对日期 |

目录中不提供凭据或临时签名 URL，不使用随时变化的随机图地址。素材 ID 不能复用于无关作品。下架时从新版目录移除并保留审核记录；已下载条目保留其原始来源和许可信息。

## 免费和授权的选择

首批优先采用项目原创素材、作者明确授权的投稿，以及逐项审核的 CC0 / 公有领域、CC BY 素材。来源页面必须支持预览、下载和计划中的再分发方式。原创或作者投稿仍须明确作者的授权范围。

- [CC0](https://creativecommons.org/publicdomain/zero/1.0/) 允许复制、修改和分发，但仍应保留来源记录，并检查其中独立的肖像、隐私或商标权问题。
- [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 需要适当署名、许可链接及修改说明。项目代码的 MIT 许可不覆盖下载的第三方素材。
- [Wikimedia Commons](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia) 可作为精选来源，图片、GIF、视频都要核对各自文件页。它并不保证每个上传内容的授权信息都正确。首批不接入通用的实时搜索代理，只维护审核过的精选目录。
- Commons 允许直接链接，但建议下载后复用。来源文件可能被改名、替换或删除，因此不宜依赖任意热链永久在线。优先在逐项确认再分发条件后保留受控副本和校验值。[官方技术说明](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/technical)
- [Unsplash API](https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines) 和 [Pexels API](https://help.pexels.com/hc/en-us/articles/4405588861721-Can-I-use-the-API-as-a-wallpaper-app) 对复制图库体验、壁纸应用及署名有具体限制，也存在针对其他用途产品的例外。不能仅依据「图片免费」就把整站图库接入。若以后考虑这些 API，应先确认本产品符合其使用条件，不列入首批默认来源。

首批暂不收录授权不明确的搬运壁纸、只注明免费下载但没有复用许可的素材。GIF 和视频数量可以少，不能为了凑齐分类跳过许可审核。

## README 友链与素材署名

实际接入后，在中文、英文 README 底部增加「壁纸素材来源与致谢」，链接到实际使用的平台、作者或素材项目，并继续保留 Linux Do 链接。不能在尚未使用时暗示已获得平台合作或背书。

友链之外，软件每个在线素材的详情页、本地下载记录和随文件保存的 `origin.json` 都应保留作者、作品来源、许可及修改说明。为需要完整文本的素材附带相应许可。可从目录自动生成逐项素材清单，避免 README 友链更新了而素材署名遗漏。友链不能替代许可要求的署名。

## 实现方式与验证

沿用 PySide6，使用 `QNetworkAccessManager` 异步请求和流式写入，不引入 WebEngine 或额外常驻服务。按可见区域加载卡片，限制缩略图缓存大小和下载并发；目录支持 ETag 与缓存回退。网络对象只在需要在线页或下载时工作。

先写入同目录的 `.part` 临时文件，校验长度、SHA-256 和媒体类型后，再原子移入 `data/wallpapers` 并保存本地条目及来源记录。中断或失败不产生已下载状态，不把整个视频读入内存。保存路径由软件生成，远端文件名不能控制目录或覆盖用户文件。文件类型只允许本软件已支持的图片、GIF 和视频。

目录优先从官方 HTTPS 地址获取。若沿用已有的 GitHub 下载加速，只能用已可信获取的目录校验原文件；不能同时从未验证的镜像接受目录与其中的校验值，否则无法证明来源。首版目录获取失败时使用上次缓存。

实现顺序为「确定首批授权素材和来源清单 → 建立索引与校验 → 在线页与懒加载 → 原文件下载和状态同步 → 断网、取消、重复下载、删除重下及损坏文件验证」。重点验证中英显示、内存、原始字节一致性、许可记录完整性，以及没有 API 密钥也能使用精选目录。
