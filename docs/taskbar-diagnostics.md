# 原生任务栏本地稳定性测试

这批稳定性修复随 v0.8.0 提供。已完成本机与模拟故障验证，其他 Windows 版本和第三方工具组合仍需结合诊断记录核对。

## 本次处理

- 监听 Explorer 对任务栏宽度、对齐和列位置的改写，合并后恢复三段布局。关闭美化时恢复最新的系统值和绑定。
- 每两秒在任务栏 UI 线程核对控件关系，识别同一 Explorer 进程中的根布局、应用列表、开始按钮和托盘替换。
- 背景根据实际按钮范围绘制，避免临时异常宽度把空背景铺满屏幕。显隐判断采用 XAML 实际位置，减少原生 Start 窗口位置滞后的影响。
- 布局持续越界或遭到密集改写时停止美化，恢复原生任务栏。全屏唤出后如果 Windows 再次降低任务栏层级，会重新置前。
- Explorer 重启后重新连接。开始与停止信号分开处理，取消时清除未消费的启动信号。

## 在出现问题的电脑上检查

1. 从托盘退出其他轻块桌面实例，解压本地测试包到可写目录。运行其中的 `轻块桌面.exe`，在桌面收纳设置中开启任务栏美化。
2. 保持使用到原先容易出错的时长。期间观察增减应用、搜索框变化、最大化、全屏与退出全屏、显示桌面、锁屏恢复、休眠恢复，以及原来使用的多屏和缩放组合。不要为测试关闭原本可能发生冲突的软件，否则可能掩盖触发条件。
3. 异常发生时记下时间和刚才的操作，保留测试目录中的 `data/still.log`。若目录不可写，日志位于 `%LOCALAPPDATA%/StillWallpaper/still.log`。日志会轮转，还应保留同目录的 `still.log.1`、`still.log.2`（如存在）。
4. 日志中的 `Taskbar start` 和 `Taskbar layout` 仅记录 Windows 构建与补丁号、组件指纹、缩放、几何尺寸和恢复计数，不记录桌面图像或应用名称。完整 `still.log` 的其他功能记录可能包含用户文件路径，分享前可以只截取任务栏记录。
5. 测试结束退出测试版，再启动原有安装版。不要同时开启两个版本的任务栏美化。

`state` 为 0 时等待控件，为 1 时布局正常，为 2 时正在恢复，为 3 时布局不兼容，为 4 时检测到持续冲突。`repairs` 是布局恢复次数，`rebuilds` 是控件重连次数。

计数在同一 Explorer 组件驻留期间可能跨多次开关累计，应比较异常前后的增量。

`changes` 为累计位标记，可相加。1 表示主框宽度，2 表示托盘宽度，4 表示应用列表宽度，8 表示所在列或跨列，16 表示对齐或边距，32 表示其他受控视觉属性，64 表示列集合。它反映被改写的位置，不能仅凭这些记录断定是哪个第三方软件造成的。

## 开发验证

```powershell
python tools/run_tests.py
.\tools\test_native_taskbar.ps1
```

第二条命令需要 Windows 交互会话，使用独立的 XAML island 模拟延迟属性改写、列集合替换、增减图标、控件移除、五种逻辑屏幕宽度和高频竞争写入，不连接或修改 Explorer。真实任务栏的显隐、系统缩放切换、休眠恢复和第三方兼容性仍需实机验证。

布局监听与回调 API 参阅 [Microsoft 的依赖属性通知文档](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.dependencyobject.registerpropertychangedcallback)。任务栏控件结构可交叉参考 [Windows 11 taskbar styling guide](https://github.com/ramensoftware/windows-11-taskbar-styling-guide)。本项目没有引入其运行时或复制其实现。
