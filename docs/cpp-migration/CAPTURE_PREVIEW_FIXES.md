# 截屏、录屏及相关收纳交互修复记录

本记录用于 C++ 测试版的迁移验收，记录本轮局部修复和实际执行的隔离回归。正式 Python 1.0.0 的 main、官网和更新渠道不由本记录改变。它不是发布成功证明，也不表示所有界面已逐像素、所有设备已逐项等价。

参考实现为保留的 Python 1.0.0 截屏、录屏和桌面收纳代码。修复期间没有关闭当前用户试用程序、重启 Explorer、接管真实桌面或读取真实剪贴板内容。

## 用户复现与对应修复

| 问题或触发条件 | 修复后的处理 | 主要代码 |
| --- | --- | --- |
| 重新框选后拖动异常，旧的录屏命令可能作用于新选区 | 重新框选保留工具栏实例，清理选区、绘制、拖动及待转换状态；递增转换序号，丢弃旧的排队命令；录屏/长截图转换在 Qt 输入回调返回后执行 | `src/capture.cpp`：`capture_command`、`capture_proc`、`select_done` |

| 文字输入框不随内容或字号变化；修改字体打断输入 | 根据实际字体及文字测量调整输入框尺寸，并限制在选区内；更新字体时保留输入控件和光标；双击继续编辑，单击已有文字可拖动，空白文字不留下空标注 | `src/capture.cpp`：`layout_text`、`start_text`、`change_style`、`commit_text` |

| 橡皮擦切换后工具栏消失；工具栏右键不等同于截屏区域右键 | 按最新要求改为可调笔宽的局部擦除，只去除笔刷扫过的标注部分并保留截图底图；可撤销，工具栏实例保留。框选状态下，工具栏及其子控件的右键行为转发为取消当前选区或退出截屏 | `src/annotation.cpp`、`src/capture.cpp`、`ui/capture_controls.cpp` |

| 快速滚动后立刻点“完成”，已捕获的末屏被丢掉 | 完成时停止新的滚轮采样，保留已有中间帧并补采一个终态帧；按顺序处理完队列才生成贴图。无法匹配末屏时保留手动拼接入口，不默默输出缺失末屏的成品 | `src/scroll_capture.cpp`：`final_sample`、`finish`、`consume` |
| 保存 PNG 或导出视频的文件对话框打开时关闭对应会话/退出程序 | 对话框返回后重新确认拥有者仍存在。截图检查窗口、对象及单调会话标识；录屏检查对象、会话开始标识、窗口、阶段及退出意图。过期结果不写文件、不启动导出 | `src/capture.cpp`：`save_image`；`src/recording.cpp`：`begin_export`、`recording_command` |
| 新图标的右键菜单打开或图标拖动期间，自动收纳计时器将其移除 | 菜单、编辑及拖动期间，重新同步和自动收纳以 200 ms 延后；交互完成后按最近截止时间调度。菜单保留路径/分组标识，不跨嵌套消息循环保留条目引用或瓦片索引 | `src/organizer_window.cpp`：`MenuGuard`、`interaction_busy`、`schedule_collect` |
| 收纳中的图标缺少管理入口，改名/移组可能在同步或保存失败后回退 | 补齐打开、目录定位、显示名、移组、还原到桌面/移除外部入口、文件拖入及跨组拖动；保存失败恢复内存中的原状态；显示名及松散图标位置持久化 | `src/organizer_model.cpp`、`src/organizer_window.cpp` |

收纳操作只修改引用及收纳配置，不移动、重命名或删除桌面原文件。“还原到原桌面”将原桌面项作为持久的桌面图标显示，不再被一分钟计时器自动收走；移除外部入口仅删除引用。这里没有宣称与 Python 原版“移动受管文件”的内部存储机制相同。

## 嵌套消息循环与调用方复核

Windows 原生菜单和文件对话框会继续处理窗口消息。仅在内层检查对象仍存在还不够：调用方返回后也必须停止访问旧引用。本轮对刚修改的调用链做了以下只读复核。

| 调用链 | 对话框/菜单返回后的处理 | 复核结论与测试范围 |
| --- | --- | --- |
| `capture_command(CaptureSave)` → `save_image` | 保存入口立即返回；失效对象使 `save_image` 返回 `false` | 隐藏贴图夹具在保存回调内销毁拥有者，再返回“确认保存”；确认无输出文件 |
| 截屏 `finish(save=true)` → `save_image` | 只有保存成功才关闭截图窗口；失效会话返回 `false`，之后直接结束 | 调用方静态复核通过；原生对话框真实点击路径仍待实机确认 |
| 原生工具栏 `WM_COMMAND` 保存分支 → `finish` / `save_image` | 分支执行完直接 `return 0`，无后续 `Surface` 解引用 | 静态复核通过 |
| 贴图 `WM_CONTEXTMENU` → `TrackPopupMenu` → `save_image` / 关闭 | 菜单返回先校验当前窗口对应的对象及单调标识；保存/关闭分支后直接返回 | 菜单外层及保存内层均有保护；真实弹出菜单期间退出尚未实机执行 |
| 原生工具栏调色对话框 | 返回后先重新定位当前 `Surface` 并比较会话标识，再写样式 | 静态复核通过；Qt 自身工具栏使用退役/延迟删除机制 |
| `frame_proc(WM_APP+84)` → `recording_command` → `begin_export` | 内层校验会话；外层刷新控件前再次校验当前会话，`frame_proc` 随即返回 | 隔离测试经过 `recording_command`，覆盖拥有者销毁、被新会话替换、标记退出三种情况 |
| 原生录屏 `controls_proc(WM_COMMAND)` → `begin_export` | 保存分支执行后直接返回；不再使用原 `Session*` | 静态复核通过 |
| 收纳主窗口 `WM_CONTEXTMENU` → `context_menu` | 使用复制的条目标识；返回时最多校验当前会话后重绘；外层立即返回 | 隐藏菜单夹具覆盖嵌套计时器与拥有者销毁 |
| 新增桌面图标 `loose_proc(WM_CONTEXTMENU)` | 弹菜单前复制路径和分组标识；返回后检查会话代数、窗口和用户数据一致性；不再读取旧 `Loose` 对象字段 | 隔离测试在菜单回调内销毁窗口及 `Loose` 对象，旧命令被丢弃 |

在上述范围内，没有发现新增保护之后调用方仍继续解引用已失效对象的遗漏。本结论不外推到未经本轮审查的全部模块。

## 2026-11-14 实测问题补充：工具条与长截图控件

用户反馈长截图预览下方按钮频闪、重叠，橡皮擦主工具条消失，以及录屏重新裁剪时菜单消失。本次修复不把隐藏橡皮擦的二级参数栏当成成功；验收对象是完整主操作栏及其原生窗口。

### 已定位并修复

- **橡皮擦主工具条**：`CaptureTools` 构造时设置的 `GWLP_HWNDPARENT` 会被 Qt 首次 `show()` 覆盖。工具栏失去与原生截屏窗口的 owner 关系后，焦点返回全屏截屏窗口时不再保证位于它之上。另一个状态差异是 Win32 隐藏 HWND 后，`QWidget::isVisible()` 仍可能为真；原先相同几何位置的刷新没有重新显示 HWND。现在在 Qt 显示和布局后核对 owner，并在原生 HWND 隐藏时显式恢复。原有隐藏/退出状态仍以 `mode < 0` 为准。
- **录屏裁剪菜单**：原来的 `show_editor` 和 `position_controls` 对所有 `phase == 6` 无条件隐藏整个录屏工具条。现在画面裁剪保留一行操作栏，提供重新框选、取消和应用；标注编辑仍使用标注工具条。操作通过原生消息队列处理，重选不会销毁录屏会话。录屏 Qt 工具条也在首次显示后校正 owner。
- **长截图按钮**：不再每个匹配任务开始时禁用按钮、完成时启用。工作期间点击撤销/手动拼接会排队，线程结束后处理；主线程不并发读取正在修改的拼接数据。预览高度变化时通过一次子窗口布局事务移动按钮并统一刷新，同一高度不重复移动。相同提示文字不反复重绘。

## 2026-11-14 局部橡皮、坐标与原版交互对照

### 本轮修复

- 橡皮不再删除整个标注对象。每次手势记录一条矢量擦除轨迹，只恢复经过区域的原截图像素；录屏导出的透明标注层在同一区域清除 alpha，后续笔迹仍能覆盖该区域。二者使用相同的像素区域，避免边缘相差一个像素。自交轨迹按圆头线段的并集处理，实时分段结果与撤销后重放一致。
- 橡皮有独立的 1–160 像素尺寸、小菜单和圆形预览，普通滚轮每整档调整 2 源像素。尺寸不改变此前笔迹。实时擦除复用同一合成位图，只更新线段覆盖区；24 步历史保存矢量数据，不保存每步全屏位图。
- 马赛克提供明确的“框选 / 涂抹”只读下拉选择；框选显示圆角、涂抹显示笔刷宽度，两者都显示像素块大小。圆角和连续涂抹路径作用于实际遮罩，越过图像边缘时纹理取样范围裁切到图像内。
- 贴图的屏幕坐标按实际客户区尺寸分别映射到源图像 x/y，避免 DPI、整数缩放和负显示器原点产生误差。放大后按源像素单元定位，橡皮圈与该源像素上的实际遮罩一致。拖出画布后保留真实轨迹坐标，由图像边界裁切，不把轨迹强行挤到边缘。
- 精确命中使用实际矩形/圆角/椭圆轮廓、箭头两翼、自由线段、马赛克遮罩和字体度量；空心图形中央不会误命中。命中容差按屏幕比例换算。普通滚轮累计满 120 后按原版文字、序号、笔宽档位变化；切换目标清除余量，长截图禁用普通尺寸滚轮，马赛克不参与普通尺寸调节。

### PNG 文件名与覆盖确认补充

PNG 保存会先将手动输入的 `.jpg` 等后缀规范化为 `.png`，随后针对**最终 PNG 路径**确认覆盖。原生保存对话框不再针对未规范化的名称先弹一次确认，避免确认了 `name.jpg` 却静默覆盖 `name.png`。确认返回后重新验证窗口、Surface identity 和 Document，窗口在模态期间销毁时不写文件。默认目录只从成功保存的最终路径更新，设置落盘失败则恢复之前的目录。

`.local/capture-regression/png-save-result.json` 对应严格编译后的隐藏窗口回归，验证了改后缀、拒绝覆盖保留字节、接受覆盖后真实 PNG 文件头、目录更新失败回滚，以及覆盖确认销毁 owner 后不得继续写入。相同进程中 `capture_pin_tests()` 的裁剪、坐标映射、导出尺寸与贴图行为检查也通过；这仍不替代最终候选的真实手势验收。

### 历史内存上限补充

Document 已提交的撤销与重做历史共用 8 MiB 的矢量数据预算，并继续保留每侧最多 24 步的数量上限；超限先丢弃最远的历史，不丢当前编辑结果。预算按矢量、文本和字体字符串的容量计算，避免仅按笔迹数量估算。一次尚未完成的手势只保留一份当前矢量回滚状态；空操作不写入历史，也不破坏重做。它不是整屏位图备份。

录屏编辑器关闭时使用 `take_history()` 移动归还历史，避免再复制一份完整历史。`history_budget_tests()` 验证大量笔迹下的预算、撤销/重做、导入过量历史后的裁切、空操作以及移动转交，实际独立回归通过。进程内存还包括当前结果、解码画面、Qt/系统共享页等；8 MiB 指历史预算，不是整个程序的内存承诺。
