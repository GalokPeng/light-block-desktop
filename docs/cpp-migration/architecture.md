# C++ 架构与隔离边界

本独立测试分支的运行时由 C++ 实现；正式 main 仍为 Python 1.0.0。默认设置界面、工具页面、桌面便签和截屏录屏工具栏采用 Qt Widgets；桌面集成、媒体与捕获服务采用 Win32 / Windows SDK，任务栏组件采用 C++/WinRT。Python 仅用于开发、构建和验证工具，不随本产品运行。原实现已归档到 `python-v1.0.0` 分支与 `v1.0.0` 标签。

## 进程和编译边界

```text
轻块桌面测试版.exe（C++23，LLVM-MinGW）
  ├─ LightBlockUi-<hash>.dll（C++，Qt Widgets，MinGW 13.1）
  ├─ 预览播放通道 → 受监督 --worker 子进程
  ├─ 桌面播放通道 → 受监督 --worker 子进程
  ├─ 原生任务栏辅助进程 / C++/WinRT 模块
  ├─ 桌面图标与系统指针的独立恢复辅助进程
  └─ 按需启动的录屏 / 缩略图 / 导出运行时
```

Qt SDK 与后端使用的 C++ 标准库不同，因此不直接链接 C++ 类接口。`src/ui_api.h` 当前为 **ABI 4**，使用带版本和结构大小的 POD 数据与函数表；`src/frontend.cpp` 与 `ui/frontend.cpp` 分别持有各自的对象。跨边界仅传递标量、字符和像素缓冲区、借用的 HWND/HBITMAP 标识、函数指针及不透明服务句柄，不传 STL/Qt 对象或异常。调用方提供结果缓冲区；会话由创建它的模块释放，输入指针的有效期不能延伸到未复制数据的后台任务。

工具服务由 `UiApi::extension(id)` 查询，各自再次检查版本与结构大小，UI 不依赖主窗口私有成员。

| Extension | POD 接口 | 默认 Qt 界面 | 后端职责 |
| --- | --- | --- | --- |
| 1 | `src/file_tools_ui_api.h` · `FileToolsUiApi` | `ui/file_tools.hpp` | 会话、后台目录/预览/摘要任务、重命名计划、应用、撤销与恢复 |
| 2 | `src/clipboard_ui_api.h` · `ClipboardUiApi` | `ui/clipboard.hpp` | SQLite 查询、选中记录、文字/图片数据、复制、固定和删除 |
| 3 | `src/focus_ui_api.h` · `UiFocusApi` | `ui/focus.hpp` | 专注/休息状态、历史、工作区读写及应用 |
| 4 | `src/launcher_ui_api.h` · `LauncherUiApi` | `ui/launcher.hpp` | 后台索引与图标缓存、检索排序、计算和选中项执行 |

截屏和录屏工具栏使用独立导出 `LightBlockCaptureUiExports`（ABI 1）和 `LightBlockRecordingUiExports`（ABI 2）。后端传状态，Qt 回传命令；捕获、标注模型、录制与编码仍由原生引擎负责。这些版本独立于主界面 ABI 4。

Qt DLL 采用内容哈希文件名；`ui-current.txt` 指定当前版本。加载前校验安全文件名和 ABI。Qt DLL、插件、样式、对应许可证与来源必须作为一套构建产物暂存，不能只复制 EXE。开发工具链在项目 `build` 目录内准备，不改全局 PATH 或原版代码。

## 界面与设置生命周期

主界面只在需要时创建，关闭后释放界面和预览，托盘及已启用的服务继续运行。设置在控件操作时保存；滑块采用短暂防抖，离开或关闭时提交尚未提交的值。保存操作从实时配置修改一个字段，不再把旧页面快照覆盖到整份配置上。修改录屏帧率不应重启收纳、任务栏或指针服务。

主界面可见时读取轻量状态更新；滚动由 Qt 的视口与绘制系统完成，不通过反复显示、隐藏和移动整页 Win32 控件实现。静图解码在后台执行，结果必须匹配当前选择代次；预览切换只停止预览通道。

默认工具页面已使用 Qt，不再嵌入旧 Win32 设置/剪贴板/文件/专注控件。旧原生页面与工具栏代码仅保留为 legacy 回退；正常启动缺少 Qt 依赖时明确报错，只有显式 `--legacy-ui` 进入旧主界面。媒体播放仍可嵌入原生子 HWND，这是渲染宿主，不是恢复旧设置弹窗。

文件工具的后台结果绑定会话和请求序号，取消或新选择会使旧结果失效；文件修改事务的日志和收尾不随页面关闭而丢弃。剪贴板详情按记录和解码代次核对，离开页面停止可见状态刷新。快速启动只在面板显示时刷新结果，目录索引和可见项目图标读取在后台运行；图标缓存及待处理队列有上限。

本地与在线壁纸预览在页面内显示；在线封面通过有并发、响应大小和解码尺寸限制的队列读取与缓存，封面不是原文件的替代。在线下载、预览和选中项使用不同状态，迟到结果不能覆盖新选择。指针样式卡片读取实际指针素材并按同一配色规则生成预览，尺寸、指针颜色和粒子颜色分别保存。

截图参数使用紧凑的上下两行 Qt 工具栏与选区侧栏，文字仍在捕获画布内编辑。工具窗口的销毁与信号回调解耦，避免原生窗口关闭时 Qt 控件仍在派发事件；布局未改变时不重复调整顶层窗口位置。录屏结束后显示贴在屏幕上的预览与工具栏，时间轴两端可拖动，方向键移动一帧，Shift 移动十帧。导出期间禁用编辑但保留取消，录制停止快捷键仅在本次录制期间注册。

## 播放与全局资源

每个媒体通道先创建挂起子进程、加入 kill-on-close Job Object，再恢复运行。请求有 token，窗口另核对 PID；迟到消息不能激活已替换请求。新请求合并为最后一次选择，旧子进程退出后再启动下一项。父进程 GUI 线程不调用媒体对象的 Shutdown；退出超时由监督层收尾。预览与桌面两个通道独立，停止其中一个不停止另一个。

静态图片由受监督的系统壁纸任务应用，原 Windows 壁纸独立备份，本测试版本不自动读取正式配置。动态媒体优先使用原生播放；不支持的媒体可采用受限的兼容播放路径。Media Foundation 编码兼容性仍受系统组件影响，不保证所有格式都能硬件解码。

媒体工作室异步探测用户选择的本地文件；原生播放不支持时可生成有超时和取消的兼容预览副本，导出仍读取原素材。GIF 导出提供快速与精确两种调色板分析，二者独立于所选输出尺寸和帧率；快速分析只缩减调色板采样。导出拒绝覆盖源文件。MP4 与无损 MKV 可保留导入媒体的音轨，普通屏幕录制仍为静音录制。

桌面图标、任务栏和系统指针先申请共享互斥资源，再使用本项目独立辅助进程和恢复记录。原版占用时拒绝接管。恢复需保留目标窗口、系统状态与请求代次；晚到的停止/失败通知不能覆盖新一轮启用意图。WorkerW 与任务栏 XAML 均涉及 Explorer 非公开行为，多版本、多屏和重启恢复必须单独验证。

## 参考与验证

迁移实验曾从独立 Python v1.0.0 源码生成界面参考图和 432 帧粒子数值。相关开发脚本不属于当前主线，不要调用不存在的 `render_python_reference.py` 或 `generate_particle_reference.py`。现有回归夹具保存在 `tests/fixtures`；若需重生成，应从 Python 归档读取模型，在隔离目录运行并审查差异，不捆绑旧运行时。数值一致不代表所有像素、指针形状或多 DPI 视觉一致。

`tools/test.ps1` 使用隔离数据目录。合成绘制、媒体编码、窗口生命周期、失效注入和模型回归只能证明覆盖到的行为；真实鼠标拖动、滚动闪烁、任务栏接管及性能仍需实机检查。证据与未验收范围分别记录，不以检查数量替代功能等价性结论。

**历史实验记录，不作为本次发行验收：** 原独立工作区的联合验证为 `.local/test-20261113-215830/summary.json`：原生检查 68/68、Qt 界面与便签检查、静图/GIF/视频实际播放、12 次通道切换及父进程退出后的子进程清理全部通过。测试使用独立配置，没有接管真实桌面或读取原版配置；结果不能推广为跨电脑、跨 Windows 版本的完整验收。界面对照与截图见 [本地迁移记录](ui-migration.md)。
