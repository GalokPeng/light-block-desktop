# 测试版资源与交互检查

此记录只针对 `cpp-preview` 分支。正式 Python v1.0.0、main、正式更新源均不变。语言改为 C++ 不代表视频帧缓冲、界面和显存开销自动消失；不能只以主进程内存宣传整套程序的占用。

## 本轮已修改

- GIF 的不透明整帧直接解码到画布；透明/局部帧复用一个有上限的缓冲。保留透明合成、恢复上一帧、恢复背景和循环语义。原始文件、分辨率和帧内容不变。
- GIF 定时把解码耗时计入帧间隔，慢帧不再排队追赶，暂停后重新建立时钟。
- 本地原生缩略图最多 32 张，Qt 显示缓存最多 24 张。以 400×225 BGRA 估计，两个像素缓存上限合计约 19.2 MiB，原上限约 54.9 MiB。该数值不包含对象、解码器、库文件映射和大图预览。
- 静态预览/元信息解码只允许一个任务运行、一个最新请求待执行；旧任务不能覆盖新选择，关闭页面丢弃待执行工作。
- 应用动态壁纸时先结束界面预览，避免同一素材在预览和桌面各保留一个无意开启的解码器。
- 长图按钮不再随每次采样反复禁用和逐个搬移；裁剪与擦除工具栏按原生窗口实际可见状态恢复，避免 Qt 状态与 HWND 状态不一致。
- 录屏音频独立工作线程、文件流式写入；停止后合并音轨时复制视频流，不再次编码原始视频。编码线程、滤镜线程和输入队列都有上限。系统声和麦克风默认关闭。
- Qt 界面默认选择其官方支持的 Windows GDI 字体数据库；显式 `QT_QPA_PLATFORM` 设置仍优先。没有移除系统字体选择、限制文字语言或修改 Windows 字体设置。Qt 6.8 的默认 DirectWrite 字体数据库在本机带来显著额外字体映射与提交内存，使用相同程序做 A/B 后才调整默认值。
- 图片原位裁剪只记录源图视口和标注历史，不为每个裁剪撤销节点复制整张原图；显示缩放、透明度、边框不写进导出像素。

## 检查范围

| 模块 | 内存/调度方式 | 必须保留的边界 |
| --- | --- | --- |
| 静态桌面 | 系统调用在受监督辅助进程，完成后退出 | 不在界面线程等待系统广播，不修改原图片 |
| GIF/视频 | 壁纸与预览分别监督；切换等旧进程退出，超时由 Job Object 回收 | 解码失败不阻塞主界面，旧消息不能提交新状态 |
| 图片库 | 虚拟列表、可见项请求、固定容量缓存 | 一万项元数据不创建一万个卡片控件 |
| 在线壁纸 | 封面最多三个并发任务、32 张内存缓存；磁盘缓存有上限 | 原文件下载校验，退出取消，不能借加速绕过本地策略 |
| 截屏/长图 | 屏幕快照按需分配，长图上限 32M 像素；撤销保留接缝信息 | 多屏/超长图本身需要较大内存，结束后释放，不能宣传恒定几 MB |
| 标注 | 合成画布只在内容变化后重绘，历史最多 24 步 | GDI/字体/DC 对象必须成对释放 |
| 录屏 | 视频写文件，音频流式 RF64；后台导出 | 不把整段视频/音频装进内存，设备失败不能静默丢声音 |
| 收纳 | 文件变化通知去抖；动画/自动收纳计时器按需运行 | 菜单/拖动中延迟重建，保持对象生命周期 |
| 鼠标粒子 | 最多 20/64/1 个粒子；静止衰减后停止动画计时器 | 不移动时不能持续全屏重绘 |
| 设置/工具 | 隐藏页停止预览，页面/语言重建后销毁旧控件 | 异步回调使用生命周期和请求代号校验 |

## 可复现测量

```powershell
./tools/test_performance.ps1 -SkipBuild
./tools/test.ps1 -SkipBuild
```

所有测量用全新隔离目录；不接管真实桌面、不录制真实麦克风/系统声音、不使用 `EmptyWorkingSet` 制造好看的内存数字。

第一次本轮性能采样：`.local/performance-20261114-001515`。53.25 秒中，静图/GIF/原生 Media Foundation 视频循环切换 12 次，成功 12 次，无遗留媒体子进程，最多一个媒体子进程。主进程后台私有内存约 8.4–8.6 MiB；此样例的主进程与媒体进程私有内存峰值约 101.6 MiB。采样 CPU 时间合计 2.92 秒，约一个逻辑核的 5.5%。这只是隐藏窗口解码测试，使用内置样例，**不是开着全部功能的整机内存，也不是公开桌面流畅度验收**；UI DLL 和 EXE 摘要均在报告中。

界面压力测试单独记录 `ui-memory.json`：初建主窗口、全部功能 fixture、十轮页面/语言/主题切换。首轮数据中，重复重建期间 QWidget 数量回到 405、GDI 为 48；私有内存从第二轮约 128 MiB 到第十轮约 125 MiB，没有观察到该循环持续上涨。这包含合成图片与工具测试，不能当作日常后台常驻内存。最终构建还需按其摘要复跑。

工作集相加会重复计算共享页，Private Bytes 是进程提交内存而非显存。GPU 显存、不同显卡驱动、真实多屏合成、音频设备权限/断开、实际录屏的音画时差，需要另外的设备实测，不能由隐藏测试推断为通过。原生 Media Foundation 静音也不能被等同于“已证明不初始化音频设备”；当前没有为这一点作无证据的承诺。

## 字体数据库的独立 A/B

2026-11-14，使用同一旧候选 EXE/UI DLL 与相同全新隔离 fixture，仅改变 `QT_QPA_PLATFORM`。证据：`.local/font-main-comparison/{directwrite,gdi}/screens/ui-memory.json`；两组完整隐藏 UI fixture 均退出 0。该组是定位字体后端影响的控制实验，不代替最终候选的功能验收。

| 阶段 | DirectWrite 私有提交 / 工作集 | GDI 私有提交 / 工作集 |
| --- | --- | --- |
| 主界面初建 | 82.6 / 162.5 MiB | 38.5 / 74.5 MiB |
| 第十轮页面、主题、语言切换 | 114.5 / 205.7 MiB | 77.1 / 120.9 MiB |

另一真实可见窗口关闭后的诊断曾显示约 966 MiB 工作集，其中约 934 MiB 为共享页，主要对应系统字体映射；私有提交约 66 MiB。未把这次现象称为 966 MiB 应用堆泄漏，也未用它替代 A/B 数值。后续仍须检查最终界面在 100%、150%、200% DPI 的中英文字形、选字列表和文字标注。没有调用 `EmptyWorkingSet` 或人为裁剪进程工作集。

接口依据：[Qt 6.8 字体后端变更](https://doc.qt.io/qt-6.10/whatsnew68.html)、[QGuiApplication Windows 平台参数](https://doc.qt.io/qt-6/qguiapplication.html)。所捆绑 Qt 6.8.3 的源码 `qwindowsintegration.cpp` 同样提供 `fontengine=gdi` 分支。

相关官方接口说明：[Media Foundation 流选择](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nf-mfmediaengine-imfmediaengineex-setstreamselection)、[应用流选择](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nf-mfmediaengine-imfmediaengineex-applystreamselections)。本轮未贸然替换已工作的原生视频渲染管线。
