# 轻块桌面二开

找到包含 `main.py`、`still/model.py` 和 `Still.spec` 的源码根目录，先读根目录的 [AGENTS.md](../../AGENTS.md)。如果本 Skill 被单独提供，用仓库中的同名文件定位这些资料。需要源码但当前只有安装包时，先找到对应版本的源码 ZIP 或 Git 检出。

## 确定交付路径

如果用户没说明改动的去向，只问一次：「这次是自行维护二开版本，还是准备向轻块桌面作者提交 PR？」已经给出目标仓库、分支或 PR 时，沿用已明确的意图。等待回答期间可以读代码、复现问题和执行本地验证。

- **自行维护**。在用户自己的仓库或分支交付。先确认当前分支及 `origin`，需要同步原项目时再使用 `upstream`。独立发布可维护自己的版本、品牌和发布权限。与官方版并存前，查阅 [项目地图](references/project-map.md) 中的实例和数据边界。
- **上游贡献**。在上游最新 `main` 的基础上建立主题分支，用作者的仓库和目标分支作为 PR 的 base。通常从自己的 fork 提 PR，有上游写权限时也可从同仓库分支提 PR。按 [贡献与合并约定](../../CONTRIBUTING.md) 准备改动、验证和 PR 说明。

两条路径共用代码、测试和许可约定。用户只要求二开时，本地改动就是交付，不推断需要推送、提 PR、合并或发布。

## 开发和验证

1. 根据 [项目地图](references/project-map.md) 找入口，从实际 UI 或后台调用链复现问题。保留数据兼容、Win32 桌面所有权、热键和进程生命周期。
2. 聚焦当前改动。新增设置需给旧配置留默认值，桌面和媒体测试使用临时配置、生成素材和独立窗口。复用现有配置、素材和文件格式。
3. 执行 `python tools/run_tests.py`。改动涉及 Explorer 桌面层、媒体渲染、系统热键或录屏时，再在 Windows 交互会话核对相应路径。用实际验证结果描述交付。
4. 需要出安装包或发布时读 [发布手册](../../docs/release.md) 与 [许可说明](../../docs/licensing.md)。版本号由发布者改动。维护第三方授权和对应源代码信息。

无法联系远端或没有凭据时，交付可审查的本地结果与远端所需的最小下一步。避免覆盖用户工作、强推、代替维护者合并或修改发布开关。
